# Local setup

M0, PRs 1, 3, 4, 5a, 5b, 6, 7, 8 and 9; M1, PRs 4, 5, 6, 7 and 8. SITREP (situation report) builds and tests locally with uv, make, a PostgreSQL container and the downloaded embedding model, offline, with no `.env` and no API key. Every CI gate is a make target, so it runs here the same way. Each PR extends this runbook in the same PR. `tests/test_runbook.py` fails when the Makefile and this file drift apart.

## Prerequisites

- **uv** 0.13.5 or later, below 0.14 (`required-version` in `pyproject.toml`). Update with `uv self update`.
- **GNU make** and **git**.
- **Python 3.12** is not a prerequisite: uv installs the version in `.python-version` on first use.
- **Docker** with Compose v2 (Docker Desktop on macOS; Engine 28 or later on Linux, because earlier engines expose localhost-published ports to the local network segment), for the database (`make up`) and `make docker-build`. `make test` needs the database.
- **`curl` and `seq`**, for `make docker-build`.
- **Port 55432 free on 127.0.0.1**, for the database. It is not 5432, so a native PostgreSQL there never answers in its place.
- **The network**, for `make audit` (PyPI and the vulnerability data), `make model` (the embedding model, about 490 MB, from Hugging Face), `make web-deps` (Chromium, about 100 MB, from Playwright's CDN), `make docker-build` (the base images) and the first `make up` (the pgvector image).
- **About 1.5 GB of free disk**: the model, and the copy of it that `tests/embeddings` makes and deletes again.

## Commands

| Command | What it does |
|---|---|
| `make help` | Lists the targets. |
| `make up` | Starts PostgreSQL with pgvector (`compose.yaml`) on `127.0.0.1:55432` and waits until it answers (below). |
| `make down` | Stops it and deletes its data. |
| `make migrate` | Applies `db/migrations` as the migration role (below). |
| `make model` | Downloads the embedding model's pinned files into `models/` and checks each sha256 (below). A second run downloads nothing. Needs the network. |
| `make load` | `make model` and `make data`, then loads the corpus into the database as the owner ("The loader (M1)" below). Needs `make up` and `make migrate` first. A second run gives the same rows. |
| `make test` | Runs `make lint`, then pytest over `tests/` without `tests/web`. Offline. `tests/db` needs `make up` and `make migrate` first, `tests/embeddings` needs `make model`, and so do the retrieval tests in `tests/db` (since M1 PR 8); all fail, never skip, without them. |
| `make lint` | `ruff check` and `ruff format --check`. |
| `make fmt` | `ruff format`. |
| `make lint-test` | CI's lint-test job: `make up`, `make migrate`, `make model`, then `make test`. Its `tests/test_secret_history.py` scans the branch's commits for secrets. |
| `make audit` | Re-resolves the lock against PyPI (`uv lock --check --refresh`), then runs pip-audit over an export of the lock with hashes. Needs the network. |
| `make docker-build` | Builds the image `sitrep:local`, then smoke-tests it (below). Needs Docker and the network for the base images. |
| `make web-deps` | Downloads Chromium for Playwright, without `--with-deps` (no apt, no root). |
| `make web-test` | `make up`, `make migrate`, `make load` (with `make model` and `make data`) and `make web-deps`, then the browser tests in `tests/web` (below). |
| `make evals` | The eval gate, offline (below). |
| `make redteam` | The red-team gate, offline (below). |
| `make data` | Regenerates the synthetic corpus into `data/synthetic/out/` (below). Offline, no database. |

The first `uv run` creates `.venv/` from `uv.lock`. The whole path from a fresh clone is the next section.

## From a fresh clone

The one documented path from `git clone` to green, with no `.env` and no API key. It is the plan's end-of-M0 verification (`docs/plans/m0-foundation.md`, "Verification at the end of M0") with `make model` before `make test` (M1, PR 4), and `tests/test_docs.py` keeps this block equal to it; M1's close moves it to the M1 plan's sequence. Clone the repository, `cd` into it, then:

```sh
make up            # PostgreSQL with pgvector on 127.0.0.1:55432, healthy
make migrate       # migrate: applied 0001_schema.sql, 0002_tables_rls.sql, 0003_loader.sql
make model         # model: 3 files match FILES at 614241f622f53c4eeff9890bdc4f31cfecc418b3 (…)
make test          # ruff, then the offline tests: all passed
make evals         # evals: no cases (min_cases=0)
make redteam       # redteam: no cases (min_cases=0)
make data          # the corpus; manifest sha256 7053bbbc…29bf5d
make docker-build  # the image, then its smoke test
make web-test      # the database loaded, Chromium, then the browser tests
```

- **Every step must pass.** Each one exits non-zero on failure, and nothing after it is worth running.
- **The network** is needed for the first `make up` (the pgvector image), the first `uv run`, which is `make migrate` (uv fetches Python 3.12 and the locked packages), the first `make model` (the model, from Hugging Face; a later run only checks it), `make docker-build` (the base images) and `make web-test` (Chromium, through `make web-deps`, and the model, through `make model`). The tests themselves stay offline.
- **One database per machine.** `compose.yaml` names the project `sitrep`, so every checkout shares one container and its data, and `make down` in any checkout deletes it for all of them.
  - A database already started from another checkout is reused: its bind mount moves to this checkout, and `make migrate` then prints `migrate: nothing to apply`. Remounting changes no data: `db/init` runs only on an empty data directory.
  - For a database that is fresh too, run `make down` first. The data is synthetic; `make up` and `make migrate` bring it back.
  - Whatever a checkout's `db/init` and migrations created stays in the shared database for every other checkout. So never run `make up` after `make down`, or `make migrate`, from a branch you have not reviewed (a Dependabot or outside branch). To get back to your own checkout's state, run `make down`, `make up` and `make migrate` there.
- **`make data`** writes `data/synthetic/out/` (git-ignored). The hash in the comment is the one `tests/synthetic/test_synthetic_corpus.py` pins.

## The database

`compose.yaml` runs one service, `db`: `pgvector/pgvector:0.8.7-pg17-bookworm`, pinned by digest (PostgreSQL 17.11). It publishes on `127.0.0.1:55432` only and mounts `db/init` read-only. There are no variables and no env file.

- **Trust auth.** The container trusts every connection into it, and is reachable only through that 127.0.0.1 publish. It is a local convenience for synthetic data: any local process can connect as any role, the superuser included. Azure is Entra-only from M3.
- **Roles** (`db/init/00-roles.sql`, run once when the data directory is created; ADR 0008):
  - `sitrep_owner`: NOLOGIN; owns the database, the schemas and everything in them;
  - `sitrep_migrator`: LOGIN; holds `sitrep_owner` `WITH INHERIT FALSE`, so it has the owner's rights only after `SET ROLE`;
  - `sitrep_app`: LOGIN; no attributes and no memberships; owns nothing, can create nothing, and can connect to `sitrep` only.

  `vector` is installed in `public`, and `public` belongs to the superuser. PUBLIC cannot connect to `postgres` or `template1` and cannot create large objects. The owner's future functions and types are not granted to PUBLIC, except a table's row type, which PUBLIC may always use and which opens no rows.
- **URLs.** `SITREP_DATABASE_URL` (the app role) and `SITREP_MIGRATION_DATABASE_URL` (the migrator) default to `127.0.0.1:55432` (`.env.example`).
  - Since M1 PR 3 they carry the prefix, as every setting does (ADR 0009). The unprefixed names are ignored, never refused: an old value, a non-default one too, is dropped and the default used. `python -m app` and `make migrate` name an unprefixed URL variable they find in the environment on stderr (`ignored: … is set`), never its value; one in a `.env` is dropped without a word.
  - Only `python -m app` reads `.env`. `make migrate` and `make load` read the environment alone: a migrator URL other than the default must be exported as `SITREP_MIGRATION_DATABASE_URL`, and in `.env` it does nothing. Every target runs `uv run --no-env-file` (since M1 PR 7), so a shell's `UV_ENV_FILE` is not loaded either; `uv run` typed by hand, without the flag, would load it. Rename the lines in an existing `.env`; one that only copied `.env.example` changes nothing, since the defaults are the same.
  - Each one must name one host, exactly `127.0.0.1`, an explicit port, its own role and the database `sitrep`, and nothing else: no password, `hostaddr`, `options` or `service`. Otherwise `Settings()` refuses it, without echoing the value.
  - `app/db/connect.py` is the only place that opens a connection. It refuses to run while any `PG*` variable is set in your shell (`PGPORT`, `PGHOST`, `PGUSER`, `PGOPTIONS`, `PGTZ` and the rest), naming the variables, not their values: unset them. It takes no connection parameter as a keyword argument, and pins `hostaddr` and `options` as well.
- **`make migrate`** runs `python -P -m app.db.migrate`:
  - it connects as the migrator, runs `SET ROLE sitrep_owner`, and refuses any other login;
  - it records each file's sha256, `session_user` and `current_user` in `sitrep_meta.schema_migrations`;
  - it stops before any DDL if an applied file changed or is missing;
  - new files run in one transaction; a file that commits, rolls back, or changes the role or `search_path` is refused and not recorded, though what it committed itself stays.

  Files are `db/migrations/NNNN_name.sql`, numbered without gaps and forward only: a fix is a new file.
- **Tables and row-level security** (`0002_tables_rls.sql`, `0003_loader.sql`): `advisors`, `mandates`, `mandate_contacts`, `documents` and `chunks`, owned by `sitrep_owner`, `SELECT` only for `sitrep_app`. Every key includes `advisor_id`. Each table has ENABLE and FORCE ROW LEVEL SECURITY and one policy: a row is visible only while the transaction's `app.advisor_id` names its advisor. With none set, every query returns zero rows, for the owner too. `documents.lang` is `german` or `english`, and its generated `tsv` uses that language; `chunks.embedding` is `vector(384)` with an HNSW index.
  - `product_sheets` is the one global table (ADR 0010): no `advisor_id`, ENABLE and FORCE, and two policies. `sitrep_app` reads every sheet inside an advisor transaction and none outside one; `sitrep_owner` alone writes. Each sheet has its exact `url` and one embedding.
  - `documents.origin` says where a text comes from (`kyc_register`, `portfolio_system`, `call_notes`, `mailbox`; `product_sheets.origin` is `product_catalogue`), and `trust` is generated from it: `untrusted` for the mailbox and for any origin not listed as internal. No statement may write `trust`, not even the superuser's. Trust is provenance, never permission.
  - `mandate_contacts` holds each mandate's recipient, from the mandate record, for M2's recipient allowlist. Ids starting with `rt-`, in any case, belong to attack documents (M1 PR 17): the schema allows them only in `documents`, as `mailbox`.
- **The app's pool** (`app/db/session.py`) connects through `app/db/connect.py`, lazily: the app starts with the database down. Each connection is checked when it is made and at every checkout (app role, no attributes or memberships, no advisor setting, its own `search_path` and no other session-level setting, its role settings as `db/init` wrote them, no held cursor, LISTEN or advisory lock) and closed if anything differs. `advisor_transaction()` is the only way to act for an advisor: a real transaction with `set_config('app.advisor_id', %s, true)`, from a `VerifiedAdvisor` that only `app/auth/` issues. Since M1 PR 8 the same statement sets pgvector's `hnsw.iterative_scan` to `relaxed_order`, transaction-locally too (ADR 0013), and the block yields an `AdvisorConnection`, a handle that ends with the block: its `execute()` returns the rows fetched in full, with no cursor or connection behind them, and after the block, or from inside the next advisor's transaction, it raises `TransactionEnded` (PR 5b sec-5). It cannot be copied or pickled.
- **`make down`** deletes the data, and the next `make up` runs `db/init` again. After a change to `db/init`, run `make down`, `make up` and `make migrate`.

Check it by hand:

```sh
docker compose port db 5432                                      # 127.0.0.1:55432
docker compose exec db psql -U postgres -d sitrep -c '\du'       # the three roles and their attributes
docker compose exec db psql -U postgres -d sitrep -c 'SELECT version()'
```

Row-level security, by hand: the superuser plants one advisor row in a transaction, sees it, and the app role, with no advisor set, does not. The rollback leaves nothing behind.

```sh
docker compose exec db psql -U postgres -d sitrep -c 'BEGIN' \
  -c "INSERT INTO sitrep.advisors VALUES ('probe', 'Probe')" \
  -c 'SELECT count(*) AS superuser_sees FROM sitrep.advisors' \
  -c 'SET LOCAL ROLE sitrep_app' \
  -c 'SELECT count(*) AS app_sees FROM sitrep.advisors' \
  -c 'ROLLBACK'                                               # superuser_sees 1, app_sees 0
```

## Running the app

```sh
uv run python -P -m app
```

It serves on `http://127.0.0.1:8000` (`SITREP_HOST` and `SITREP_PORT` change that). Use `http://127.0.0.1:8000`, not `localhost`: since M1 PR 5 every route answers 400 to any other Host, with the dev login on or off (DNS rebinding; ADR 0009). `SITREP_ALLOWED_HOSTS`, a comma-separated list of exact lower-case `host[:port]` values, replaces `127.0.0.1:<port>` when set (the image's smoke test names its published address; M3 the Azure host). With `SITREP_HOST=127.0.0.1` it may name only `127.0.0.1` and `localhost`: whoever answers the browser's DNS could rebind any other name. On another bind, a single-label name (`sitrep`) or a `.local` name is refused, since anyone on the network can answer for it; name only hosts whose DNS you control. A refused value stops `python -m app` with exit 2, naming the variable and the rule, never the value. Routes: `/`, the advisor page (since M1 PR 11, "The advisor page (M1)" below), with its `/static/app.js` and `/static/app.css` and nothing else under `/static/`; `/health`, which answers `{"status":"ok"}`; `/api/mandates`, the signed-in advisor's mandates (401 without a login, 503 with the database down); since M1 PR 12, `POST /api/ask` ("Asking (M1)" below); and, with the dev login on, `/dev/login` and `/dev/logout` (below). There are no docs or OpenAPI routes, and a trailing slash is a 404, never a redirect. The app holds a pool on `SITREP_DATABASE_URL` that connects nobody until a route needs it, so it starts and answers `/health` with the database down. `python -m app` takes no arguments: `--uds`, `--fd` and anything else exit 2.

- **Settings** come from the environment. `python -m app` is the only place that also reads a `.env` in the working directory; `Settings()` elsewhere, tests included, never does. Variable names are in `.env.example`. Since PR 7 they carry the prefix `SITREP_` (`SITREP_HOST`, `SITREP_PORT`, `SITREP_DEV_AUTH`, `SITREP_TRACE_PLAINTEXT`; ADR 0009): a shell's own `HOST` (tcsh exports one) is ignored. Rename them in an existing `.env`. Since M1 PR 3 the database URLs carry the prefix too ("The database", "URLs"), and since M1 PR 6 the model: `SITREP_MODEL`, formerly `ANTHROPIC_MODEL`. The API key alone keeps its name, `ANTHROPIC_API_KEY` ("The model client").
- **`PYDANTIC_SETTINGS_DEBUG`**, set in any case and to any value, makes `Settings()` refuse to build, and `python -m app` exit 2: under it pydantic-settings logs every setting's raw value, the API key in `.env` included.
- **Flags** (`SITREP_DEV_AUTH`, `SITREP_TRACE_PLAINTEXT`) are on only for exactly `1`. `true`, `yes` or ` 1` are off.
- **Traces** go to stdout, one JSON span per line, through the allowlist of ADR 0007: method (standard ones only), route template, status code, scheme and protocol version. No path, query, header, cookie, client address or exception message. Trace ids come from `secrets`.
- **Logs** go to stderr: time, level, logger, the message template without its values, the exception type (and errno) and the trace id. No access log. Since M1 PR 5 an exception in a thread, one escaping the main thread, one that cannot be raised (a `__del__`), one in an asyncio task nobody awaited, and a warning log a fixed message with the type (or the warning's category, at WARNING) and the trace id, instead of Python's traceback or text on stderr. A hook that cannot log writes one fixed line instead. asyncio's own logger keeps a fixed message too, for loops without the app's handler, and a report without an exception keeps its level as `an asyncio report`. `python -m app` applies the redacting log config before anything else. `python -m app` installs these; tests and other runners keep Python's hooks unless they call `install_exception_hooks()`.
- **Every response** carries `X-Trace-Id`, the strict CSP and the other security headers; API responses also `Cache-Control: no-store`.
- **`SITREP_TRACE_PLAINTEXT=1`** prints spans unfiltered, for local debugging only. The app refuses to start with it (exit code 2) unless it binds exactly `127.0.0.1`, and, since M1 PR 5, while any `OTEL_INSTRUMENTATION_HTTP_CAPTURE_HEADERS_*` variable is set, in any case and to any value: the captured headers, the session cookie among them, would print.

Check it by hand:

```sh
curl -i 'http://127.0.0.1:8000/health?q=secret'   # headers; the span on stdout has no q=secret
curl -i 'http://127.0.0.1:8000/health/'           # 404
```

## The dev login (M0)

A local login for the synthetic advisors, until Entra ID in M3 (ADR 0009). It runs natively only: the image does not carry it.

```sh
SITREP_DEV_AUTH=1 uv run python -P -m app                    # serves the login on 127.0.0.1:8000
SITREP_DEV_AUTH=1 SITREP_HOST=0.0.0.0 uv run python -P -m app # exit 2: refused before binding
```

Open `http://127.0.0.1:8000/dev/login`, pick an advisor, then open `/api/mandates`: it lists that advisor's mandates only, scoped by row-level security (`make up`, `make migrate` and `make load` first; without the corpus the list is `[]`). `Sign out` on the login page ends the session.

- **Where it runs.** With `SITREP_DEV_AUTH=1`, the entry point exits 2 before binding unless `SITREP_HOST` is exactly `127.0.0.1` (not `localhost`, `0.0.0.0`, `::` or `127.0.0.2`) and `SITREP_PORT` is not 0, and when `app.auth.dev_shim` cannot be imported. After startup it checks every listening socket again. `create_app()` mounts the shim only behind that bind.
- **Browser defences.** Every request must come from `127.0.0.1` itself (the TCP peer; 403 otherwise) and needs `Host: 127.0.0.1:<port>` exactly (400 otherwise: DNS rebinding). Every method but GET needs `Origin: http://127.0.0.1:<port>` exactly, and `Sec-Fetch-Site: same-origin` when sent (403 otherwise: CSRF). `curl` needs `-H 'Origin: http://127.0.0.1:8000'` for a POST.
- **Sessions.** In process memory: a restart signs everyone out. The cookie is HttpOnly, SameSite=Strict, Path=/, signed with a key drawn at startup. Only advisors can log in. Headers, query parameters and other cookies never name the advisor.
- **Trusted:** any local process, as with the database. Cookies ignore ports: another server on `127.0.0.1` receives the session cookie.

## The harness (M0)

`app/harness/` holds the interfaces the M1 agent loop builds on (ADR 0001). Nothing in M0 calls a model or runs a tool; the checks below already hold.

- **Tool registry** (`tools.py`). A tool is a `ToolSpec`: name, description, a pydantic arguments model, a result type, an `Effect` (READ, DRAFT, SIDE_EFFECT), a `DataClass` and `requires_approval`. `ToolRegistry.register()` refuses a spec, naming every rule it breaks, unless: DRAFT and SIDE_EFFECT tools require approval; READ tools return `Untrusted[...]`; every object in the arguments' JSON schema, `$defs` included, has `additionalProperties: false`, and every value has a type (no `Any`, no `dict[str, Any]`, no bare `list`); no field name, alias or alias choice contains an identity term (`advisor`, `user`, `principal`, `tenant`, `owner`, `identity`, `role`, `on_behalf`, `berater`, `benutzer`, `mitarbeiter`, in any case and with any separators) and every name is plain ASCII; the arguments model and every model nested in it are frozen. The schema is asked for once: what `schema()` returns, and M1 sends, is the one that was checked. A `Json[...]` field (an object inside a string) is refused. The substring match also refuses names such as `username`, `ownership` or `parole`, by design. `validate_call()` returns a `ValidCall` or a `RejectedCall` with structured errors (type, location, message). No input value is copied into an error: pydantic's message is kept only for the error types in `SAFE_MESSAGES`, every other type gets a fixed message. The location can carry key names the model sent, so traces record error types only (M1). An identity key in the arguments gets `identity_argument`.
- **The MVP tools** (`mvp_tools.py`): `search_client_docs` and `get_portfolio` READ, with handlers since M1 PR 8 ("Retrieval (M1)" below), `draft_email` DRAFT and `create_followup` SIDE_EFFECT, both with approval and declared only until M1 PR 14. All four CONFIDENTIAL. No argument names an advisor. Every field is bounded, the models are frozen, and `draft_email`'s recipients are a tuple, so a validated call cannot change.
- **Untrusted results** (`context.py`). `Untrusted[T]` holds a result and its `Provenance` (tool, record ids). It is not a `str`: `str()`, `format()`, f-strings, `%` and `+` raise, `repr()` shows a random reference and the provenance only. `wrap()` is the one sanctioned way to the text (`_value` is reachable, by convention unread outside `context.py`), inside `<untrusted tool="…" records="…">`, with text and provenance escaped so the text cannot close the delimiter; the cost is that the model reads `&`, `<` and `>` as entities.
- **Protocols** with their contracts in the docstrings: `TokenBudget` (`context.py`), `ApprovalGate` (`approval.py`), `OutputPolicy` (`policy.py`, M2), `ModelClient` (`model.py`, built by `model_client.py` since M1 PR 6: "The model client").
- **Embeddings** (`app/embeddings/`). The `Embedder` protocol adds the `query: ` and `passage: ` prefixes itself. `FakeEmbedder` keeps serving tests that need no model: 384 dimensions, unit length, deterministic from SHAKE-256, model id `fake/intfloat/multilingual-e5-small` and revision `fake`, so its vectors cannot pass for the real model's. The real one is next.

## The embedding model (M1)

`intfloat/multilingual-e5-small` at a pinned commit (ADR 0005), run by onnxruntime on the CPU. The loader calls it (below), and the search handler embeds each query with it ("Retrieval (M1)"); `POST /api/ask` loads it at the first ask ("Asking (M1)").

- **`make model`** downloads exactly the three files of `FILES` in `app/config/embedding.py` (`config.json`, `onnx/model.onnx`, `onnx/tokenizer.json`, about 490 MB) at `REVISION` into `models/intfloat/multilingual-e5-small/<revision>/`, which git ignores and the image's build context leaves out.
  - `python -P -m app.embeddings.model_files missing` deletes a file whose bytes differ and lists what to fetch, so a second run downloads nothing and only checks.
  - curl fetches each file anonymously: `-q` first, so no `~/.curlrc` applies; https only, for redirects too; TLS 1.2 or later; nothing over 600 MiB. The file lands in a fresh temporary file beside its target, then is renamed; a failed or interrupted download removes the temporary file.
  - `… model_files verify` checks every sha256, deletes a mismatch and fails, naming the file. No cache, locally or in CI.
- **Every load reads through `read_verified()`** (`app/embeddings/model_files.py`): the bytes, once, only when their sha256 is the pinned one. A missing file, a link (even to the right bytes), a linked directory on the way to the file, a FIFO, a directory and anything over 1 GiB are refused unread, and `make model` neither deletes nor downloads through a link. The model directory itself may be a link, to a shared disk say. onnxruntime and tokenizers get those very bytes, never a path.
- **The graph check** (`app/embeddings/onnx_graph.py`) runs on the model's bytes before onnxruntime parses them. It reads the protobuf with the standard library, and refuses a tensor with external data anywhere (initializers, sparse initializers, node attributes, subgraphs), any operator domain but the standard one, model-local functions, training info, an `ort_config` entry in the metadata, subgraphs nested deeper than 16, and a malformed file. It reads what onnxruntime's protobuf parser reads: a tag wider than 32 bits, which that parser would read under its low 32 bits, is malformed, and a `data_location` other than exactly DEFAULT is refused, since the parser casts the enum to 32 bits. The pinned model has 1243 nodes in the standard domain, opset 11, and no external data.
- **The session** (`app/embeddings/onnx.py`) runs on `CPUExecutionProvider` only (the wheel also ships an Azure provider that calls remote endpoints), parses the ONNX format only, computes deterministically, and registers no custom operator library. The model's metadata never configures it: `read_config_from_model=0`, and while `ORT_LOAD_CONFIG_FROM_MODEL` is set at all, the embedder refuses to load. Its inputs must be `input_ids` and `attention_mask`, and may add `token_type_ids` (all int64); its output must be `last_hidden_state` with 384 dimensions. A refusal names the expected inputs, never the model's.
- **Vectors** follow the model card: the prefixed text through the model's own tokenizer, the last hidden state averaged over the attention mask, then divided by its L2 norm. Nothing is truncated: an input over 512 tokens, prefix and special tokens included, raises `TextTooLong`, whose message carries counts only.
- **Passages** (`app/embeddings/chunking.py`): `chunk(text, tokenizer)` cuts a document into passages of at most 400 tokens of the model's tokenizer, `passage: ` and the special tokens included. Each passage is a verbatim slice of the text without its surrounding whitespace; the slices run end to end with no overlap. A cut falls on a token boundary in the second half of its window, at a blank line if there is one, else a line break, a sentence end or a space. The synthetic corpus's longest document counts about 170 tokens, so each document is one passage.
- **Nothing downloads at runtime.** `tokenizers` requires the Hugging Face Hub client only for `Tokenizer.from_pretrained()`; `pyproject.toml` excludes it from the lock (`exclude-dependencies`), so it is not installed, and the import allowlist bans `from_pretrained` in `app/`. The HTTP library under it, `httpx2`, is installed since M1 PR 6 for the model client alone; the embedder loads neither it nor the SDK.
- **Measured** on an Apple M1: load 1.5 s (reading and hashing the files 0.5 s, the session 0.8 s); about 60 passages per second at about 90 tokens each. CI's figures are in the PR 4 description.

## The model client (M1)

`app/harness/model_client.py` (ADR 0012) talks to the Messages API. `POST /api/ask` builds it at the first ask and calls it through the loop ("Asking (M1)"). Tests never reach the API: they send to `httpx2.MockTransport`.

- **The key.** Timur's alone: create a workspace for SITREP in the Anthropic Console, set its monthly spend limit, create one key in it, and put it in your own `.env` as `ANTHROPIC_API_KEY=…`. Never in CI, the image or a GitHub secret; the agent never reads or sets it. Empty is no key. `Settings` holds it as a `SecretStr`, so `repr`, `str` and JSON show stars. A key with a space or a non-ASCII character is refused without being shown. Without a key the app starts; the client cannot be built.
- **Rotation.** Create a new key in the workspace, replace the line in `.env`, restart, then revoke the old key. Do it at once if the key may have leaked.
- **The model** is `SITREP_MODEL`, default `claude-sonnet-5-5`. A model without a price in the table refuses start.
- **Refused variables.** Every variable whose name starts with `ANTHROPIC_`, in any case, except `ANTHROPIC_API_KEY`, makes `python -m app` exit 2 before it binds, naming the variable, never its value. The SDK reads such variables for its base URL, other credentials, extra headers, its log level and prompt content in its spans. `ANTHROPIC_MODEL` is among them: rename it. The key itself, exported in the shell (even empty), refuses start too: the environment wins over `.env`, so another workspace's key, without the spend limit, would replace yours unseen. Keep it in `.env` only. If your shell exports one of these, unset it for the app: `env -u NAME uv run python -P -m app`. `import anthropic` applies `ANTHROPIC_LOG` as it loads, before the refusal; the refusal comes before any request.
- **Invalid settings** (a malformed key, a database URL off loopback) make `python -m app` exit 2 with the variable and the rule, never the value: pydantic's error details would carry the value itself.
- **The client** gets the key explicitly, so the SDK reads no token, profile or config directory, and sends only to `https://api.anthropic.com`. Its HTTP client ignores proxy variables, `SSL_CERT_*` and netrc, follows no redirect, retries nothing, and times out after 120 s (5 s to connect). It trusts the platform's roots: the system store on macOS (through `truststore`, so a root installed by a profile counts), OpenSSL's bundle in the Linux image. The SDK's spans and trace-context headers are off. The loggers of `anthropic`, `httpx2` and `httpcore2`, children set lower included, are held at INFO or above: at DEBUG the SDK logs the prompt and the response headers. Code that lowers one after the build is not stopped. A failed call raises `ModelCallError` with a kind (`timeout`, `connection`, `status`, `response`) and the HTTP status, nothing from the request or the response. A tool that is not exactly `{name, description, input_schema}` (a server tool, say), or a system prompt that is not one text, raises `RequestRefused` before anything is sent. Responses are validated strictly: a body that does not fit the SDK's types, or a content block it does not know, is `ModelCallError("response")`, without pydantic's warnings, which would quote the body on stderr. The messages themselves are not checked yet: a block with a URL source would make the API fetch it, so the loop (PR 10) checks them.
- **Cost.** `cost_usd(model, usage)` is the response's usage times the price table of 2026-11-09 (USD per million tokens, Sonnet 5.5: input 2, 5-minute cache writes 2.50, 1-hour cache writes 4, cache reads 0.10, output 10), times 1.1 for US-only inference. Usage it cannot price raises `PriceUnknown`: another model or geography, the priority or batch tier, fast mode, server tool use, counts that are not counts. A failed call reports no usage, though generated tokens may be billed (the loop's budget, PR 10). A new price is a dated edit in the code and in ADR 0012, which a test keeps equal.
- **Live calls** are Timur's, by hand, after a cost estimate (`! …`, plan default 17).

## The loader (M1)

`make load` runs `make model` and `make data`, then `python -P -m app.db.load` (ADR 0010), which writes the corpus into the database. Run `make up` and `make migrate` first.

```sh
make load   # load: corpus 7053bbbc4bd2...: 40 mandates, 344 documents, 6 product sheets
            # load: alice: 14 mandates, 14 contacts, 124 documents, 124 chunks (bob, carol likewise)
            # load: product sheets: 6
```

- **Who writes.** The app role only reads, so the loader logs in as the migrator and runs `SET ROLE sitrep_owner`; any other login is refused (the app role cannot `SET ROLE`; the superuser can, and is refused). It writes one advisor per transaction through `owner_advisor_scope()` in `app/db/session.py`, which checks the session again (the migrator's own login acting as the owner, neither a superuser nor BYPASSRLS, the role's own `search_path`, no advisor set yet, no temporary tables), takes only the cast's advisors, and sets the advisor for that transaction. FORCE binds the owner, so row-level security scopes every statement, and WITH CHECK and the composite foreign keys refuse a row of another advisor. The product sheets follow in a transaction of their own. No route or request code can reach the loader or the helper (`tests/test_loader_scope.py`).
- **What it takes.** Only the reviewed corpus: `manifest.json` must hash to `MANIFEST_SHA256` in `app/db/load.py` (the value `tests/synthetic/` pins), and every file to its manifest entry. Then every record is checked before anything is written: `origin` from the record's type, never from the record, and a record whose own `origin` or `trust` disagrees is refused; ids are unique lower-case slugs, none starting with `rt-`; the advisors are the cast's, and each document's advisor is its mandate's; each mandate's contact is its record's `client_email`, a lower-case address on the staff domain, used by no other mandate and by no one of the cast; each sheet's `url` is exactly `https://<staff domain>/<produkte|products>/<slug>` for its language and id; title and body together at most 32,000 characters, without a NUL, valid UTF-8 text. A refusal names the file, the record id and the rule, never the text (an unexpected key only when it is a plain field name), and exits 1. A database error prints its type, SQLSTATE and primary message only, since its detail line can carry a row.
- **What it writes.** Each advisor's mandates, contacts, documents and chunks are deleted and written again in that advisor's transaction (never `TRUNCATE`, which ignores row-level security); the advisor row is upserted. So a second load gives the same rows, and a load without attack documents leaves none. Documents are cut into passages of at most 400 tokens and embedded with the model; every vector stores the model id and revision. A product sheet is one passage and one vector; a longer one is refused, never cut. Everything is cut and embedded before the first write.
- **Attack documents** (M1 PR 17) enter only through `load_attack_documents()`: ids starting with `rt-`, into a mandate of the corpus, under that mandate's advisor, always as `mailbox`. The command line has no flag for them yet.
- **Measured** on an Apple M1: about 8.6 s for the whole corpus (350 passages: 344 documents and 6 sheets), the model's load included.
- **Local only.** The image carries neither `data/` nor the model. In Azure the loader gets its own identity, separate from the migrator (M3).

## Retrieval (M1)

`app/harness/handlers.py` (ADR 0013) holds the READ tools' handlers, `search_client_docs` and `get_portfolio`, apart from their declarations in `mvp_tools.py`. `read_handlers(pool, embedder)` binds them to the app's pool and embedder by tool name, read-only. `POST /api/ask` passes them to the loop ("Asking (M1)"). Each handler checks its call first (a `VerifiedAdvisor` and its own arguments model, else `TypeError`), runs in its own advisor transaction, and returns `Untrusted` with the tool and the record ids in order; it logs nothing.

- **Search.** The query is embedded first, outside the transaction. Then three ranked lists of at most 20 records each: full-text search in English and in German, each statement keeping to its own language's documents and product sheets, and the nearest vectors of the query's model and revision, a document by its nearest passage. Reciprocal rank fusion (k = 60) joins them; ties go by kind and id, so the same query gives the same hits. `limit` (1–20, default 8) cuts the fused list.
- **A mandate id** is looked up inside the transaction first. Another advisor's mandate is not there, so it answers like an id that exists nowhere: no hits, and a `null` portfolio. With a mandate, only its documents are searched, and no product sheet.
- **A hit** is `{kind, document_id, mandate_id, title, lang, trust, excerpt}`: `kind` is `document` or `product_sheet` (whose `mandate_id` is `null`), `trust` comes from the record's own column, and `excerpt` is the stored passage nearest the query, whole (a sheet is one passage), read in the same statement as the trust, so both come from one snapshot.
- **`get_portfolio`** returns the mandate's report from the portfolio system (`origin` `portfolio_system`), so an e-mail dressed as a report is never it: `{mandate_id, document_id, title, lang, report}`. No document carries a date the database stores; the report's text names its reference date.
- **Refusals.** A query over the model's 512 tokens (500 characters can tokenize to about 2,000) raises `ToolFailed("query_too_long")` before any connection is taken; nothing is cut. A row of another advisor, which row-level security should never pass, makes the handler raise `GuardError` rather than return it.
- **Indexes.** No index on `tsv`: `@@` is not leakproof, so under row-level security the planner reads the advisor's rows through the primary key and filters them, and a GIN index could serve no app query (measured; `tests/db/test_retrieval.py`). At this corpus's size the vector search sorts the advisor's own rows too; the HNSW index and `hnsw.iterative_scan` take over on a larger corpus, and the test proves them with the planner pushed onto the index.

Search by hand, as Alice's transaction would (`make load` first):

```sh
docker compose exec db psql -U sitrep_app -d sitrep -c 'BEGIN' \
  -c "SELECT set_config('app.advisor_id', 'alice', true)" \
  -c "SELECT advisor_id, id, ts_rank_cd(tsv, q) AS rank FROM documents, websearch_to_tsquery('german', 'Vermögensbericht') q WHERE lang = 'german' AND tsv @@ q ORDER BY rank DESC, id LIMIT 3" \
  -c 'ROLLBACK'   # Alice's documents only, best rank first
```

## Asking (M1)

`POST /api/ask` (`app/api/ask.py`, M1 PR 12) answers one question of the signed-in advisor with the agent loop (`app/harness/loop.py`, ADR 0001) over the two READ tools. Each live call costs money and is Timur's, by hand (plan default 17); the tests use a scripted model and never reach the API.

```sh
make up && make migrate && make load                 # the corpus, with the model
SITREP_DEV_AUTH=1 uv run python -P -m app            # the key in your own .env
curl -sS -c jar -H 'Origin: http://127.0.0.1:8000' -d advisor=alice http://127.0.0.1:8000/dev/login >/dev/null
curl -sS -b jar -H 'Origin: http://127.0.0.1:8000' -H 'Content-Type: application/json' \
  -d '{"question": "What do I need to know before the call with Weber?"}' http://127.0.0.1:8000/api/ask
rm jar                                                # the session cookie
```

- **In:** `{"question": "…", "mandate_id": "…"}`, `mandate_id` optional: without it the ask covers all of the advisor's own mandates, and the model is told of none in focus; with it, the model is told that mandate's id and its tools look it up under row-level security (another advisor's mandate finds nothing). **Out:** `answer`; `citations`, each `{record_id, title, kind}` (`document` or `product_sheet`), for each cited id a tool returned, in the order cited; `grounding`, `{figures, unmatched, unknown_citations}` (PR 9's counts); `proposals`, `[]` until M1 PR 14; `usage`, `{input_tokens, output_tokens}`; `cost_usd`, an exact decimal string such as `"0.02560"`; `stop`, one of `end_turn`, `refusal`, `budget` and `max_turns`; `trace_id`, the same as `X-Trace-Id` (always set when the app serves the request). JSON only, with `Cache-Control: no-store`.
- **In this order:** the login (401) and, with the dev login, `Origin: http://127.0.0.1:<port>` exactly (403, before any route); the content type (422); the rate limit (429); the body (422); the key, then the embedding model, then the database (503); then the loop.
- **The body:** exactly one `Content-Type`, exactly `application/json`, checked before the rate limit counts, so a cross-site form (`text/plain`, which needs no CORS preflight) cannot spend an advisor's asks; then at most 32 KiB as it arrives (the longest valid ask, every character escaped, is about 24.8 KB), a JSON object of exactly `question` (1 to 2,000 characters, not blank) and, if sent, `mandate_id` (letters, digits, `-` and `_`, starting with a letter or digit, at most 128). Anything else gets one fixed `{"detail": "invalid request"}`, which repeats nothing it was sent.
- **The rate limit** is per advisor, in process memory: 10 asks started in any 60 seconds, and one at a time. A refused ask and another content type do not count; a malformed body does. The slot is free again when the route returns, before the answer is sent. A restart clears it, and a second instance would have its own (M3).
- **The deadline:** no model call starts 90 seconds or more after the request arrived (the first ask's builds count too); the answer is then empty, with `stop` `budget`, as when the request's 150,000 tokens run out. The loop reads no clock: the route wraps the model client (Timur's answer 1 on #33). It is no wall-clock bound: a call already running ends within the client's timeouts (120 s per phase, 5 s to connect; ADR 0012), and the tool calls of its turn still run, each statement without a timeout until M2 (PR 8's sec-4, deferred).
- **503** names its cause: `model unavailable` (no key), `search unavailable` (no model files: `make model`), `database unavailable` (`make up`). The model client and the embedder are built at the first ask, not at startup, so `/health` answers without them; the first ask waits about 1.5 s for the model, during which the app answers nothing else. A missing key and missing or unpinned model files are kept until a restart, since the settings and the model files are read once; another failure to load the model (an I/O error, say) is tried again at the next ask.
- **Connections.** Before the first model call one advisor transaction checks the database; each tool call then opens and closes its own; the citations' titles come from one more. None is held while the model is called.
- **Failures** have one fixed body each: `the model call failed` (502), `database unavailable` (503, a database that stops answering mid-request), `the request failed` (500: a row of another advisor reached a handler or the citations' lookup, a reply outside the contract, or anything unexpected). The trace id finds the span, which carries the error's kind (`sitrep.loop.error`: `guard` for a broken boundary, `database`, and the loop's own kinds), from the loop and from the route's own transactions alike.
- **What the model sees of a refused call:** `query_too_long`, the one reviewed kind (`handlers.TOOL_FAILURES`), so it can shorten the query; any other failure is `tool_failed`.

## How the toolchain is pinned

- **Lock.** `uv.lock` pins every package with hashes. The Makefile exports `UV_LOCKED=1`, so uv fails instead of rewriting the lock when it disagrees with `pyproject.toml`. After a dependency change, run `uv lock` and commit both files.
- **Minimum release age: 7 days.** `exclude-newer = "7 days"` in `[tool.uv]`: nothing uploaded to PyPI in the last 7 days is resolved. uv records the span in the lock (`exclude-newer-span = "P7D"`), not a timestamp, so the lock does not go stale as days pass. uv 0.13.5 and 0.13.6 both accept it. The policy does not cover the build backend `uv_build`, which the lock never resolves; the exact uv pin is the control there (ADR 0006). It is in place in the Dockerfile (PR 3; the image build does not download `uv_build`) and in CI (setup-uv `version: 0.13.5`, PR 4); a test keeps the two equal.
- **`sys.path`.** pytest runs as `python -P -m pytest`, so the working directory is not put in front of the standard library. The editable install still appends the repository root (its `.pth` file, a consequence of `module-root = ""`), so `evals`, `redteam` and `data` are importable as namespace packages. `tests/test_data_dirs.py` is what keeps the data in them inert.
- **pytest plugins load by name only.** `--disable-plugin-autoload -p pytest_socket`: an installed package's `pytest11` entry point (platformdirs, a dependency of pip-audit, declares one) does not run.

## Evals and red team in M0

`make evals` and `make redteam` run `python -P -m app.runners.evals` and `…redteam` over `evals/` and `redteam/`. Each suite has a `gate.toml` (`min_cases`), a case directory (`evals/cases`, `redteam/attacks`, one `<name>.json` per case) and `recorded/<version>/<case id>.json`. In M0 the runners check the corpus and score nothing:

- an empty corpus passes and prints `evals: no cases (min_cases=0)`; a corpus with cases fails closed until scoring arrives in M1;
- a stray file or symlink, invalid JSON, a duplicate key or id, an orphan recording, or a recording with an `authorization`, `proxy-authorization`, `x-api-key`, `api-key`, `ocp-apim-subscription-key`, `cookie` or `set-cookie` header fails, as a key or as a value (HAR-style name/value pairs). Header values are not scanned here; `tests/test_no_secrets.py` scans every committed file, recordings included;
- text is read as NFKC, with ideographic dots as `.` and without invisible format characters (zero-width, tags), before the rules below;
- cases name the cast, the bank, the product and the domains only through placeholders such as `{advisor.<id>}`, `{email.<id>}`, `{domain.attacker}` and `{mandate.demo}`, resolved from `app/config/branding.py`; a literal name or an unknown placeholder fails;
- after resolution, every host in a URL (a scheme with one or more slashes or backslashes, or `//`; tab, CR and LF before a dot are dropped, as browsers do), an e-mail address or a bare name must end in the label `example`. IP literals, `localhost`, `xn--` and non-ASCII labels fail. A bare file name such as `report.pdf` reads as a host: put it inside a URL, or write it without the dot;
- `--live` needs `--yes`, and live runs are refused in M0.

Errors name the file (escaped unless it is a plain name, so no file name can start a GitHub workflow command), the JSON path and the rule, never the text. `min_cases` must equal the committed case count (`tests/runners/test_runner_gate.py`), so deleting a case alone fails; deleting it and lowering `min_cases` in the same change passes, and the ask on `gate.toml` and the review are the control for that.

## The advisor page (M1)

`/` is a box for one question. Ask sends `POST /api/ask` with `{"question": …}` (the plan's contract; the route is "Asking (M1)" above; the page sends no `mandate_id`, so an ask covers all of the advisor's own mandates), and shows:
- the answer, as written, line breaks kept, in a box labelled as model output (it can quote e-mails and documents, nothing in it is a clickable link, and the advisor is told not to copy addresses from it into a browser);
- the stop reason, when the loop stopped early or the model declined;
- the sources: title, kind and record id of each cited record;
- the grounding counts: "n of m figures found in the sources" and the number of cited ids that no source returned. Never "verified": the number guard shows where a figure was found, not that it is right, and a figure from an attacker's e-mail counts as found (`app/harness/grounding.py`);
- the trace id, the cost in USD and the tokens.

A failure is stated with the response's `X-Trace-Id`, when that is 32 lower-case hex digits: 401 (not signed in), 403, 422, 429, 503 (the page does not say why; locally it means no model key or no database), any other status, a network error and a redirect, which is not followed. A response that does not match the contract renders nothing ("Unexpected response."). Ctrl+Enter or Cmd+Enter asks too.

**Untrusted output.** The answer is model output and a title can come from an e-mail, so `app/web/static/app.js` puts every value onto the page through `textContent`: nothing is parsed as HTML or Markdown, the only elements it creates are list items and spans, and no link, image, attribute or request is built from a response. An `<img>` or a reference-style link in an answer stays visible as text. The page loads one script and one stylesheet from its own origin, two exact routes, under the strict CSP, with no inline script, style or handler. The box has no `name`, so a form submitted without the script carries no question into a URL, and it turns off spell check and autocomplete, so a browser's enhanced spell check does not send what the advisor types to its vendor. `tests/test_ui_page.py` scans `app.js` for the sinks that would break this: `innerHTML`, `setAttribute`, URL properties, `new`, the global object, any `document` member but `getElementById` and `createElement`, computed or string-keyed members, an alias of `fetch`, a second `fetch`, unicode escapes, block comments and the rest, each rule with its own planted shape. It scans the stylesheet for anything that loads a resource. It is a lint over our own code, not a proof; the browser tests are the guard.

## Offline tests

pyproject sets `--disable-socket --allow-hosts=127.0.0.1,::1` for pytest. A TCP `connect()` on a Python socket to an address other than `127.0.0.1` or `::1` raises `SocketConnectBlockedError` (`tests/test_network.py`).

Two checks keep the block from being switched off:
- **The effective configuration.** pytest's own view must show `pyproject.toml` as the config file, the socket block on, exactly those two hosts allowed, and no force-enable. This holds wherever an option came from: another config file, `PYTEST_ADDOPTS` or the command line.
- **A text scan.** Every `.py`, `.toml`, `.ini` and `.cfg` file git sees, plus the Makefile and `.github/`, is checked for pytest-socket's opt-out markers, fixture and flags. Code that rebinds socket functions directly is not detected.

Not covered:
- UDP `sendto()`;
- `connect_ex()` (unverified);
- DNS lookups through libc;
- subprocesses and native libraries;
- anything reached through a loopback proxy or tunnel, such as an `HTTPS_PROXY` on 127.0.0.1;
- code that runs at import or collection time, or in fixture teardown. Suspected, not verified: pytest-socket applies the block per test, in setup.

Later PRs keep those offline through loopback-only URLs and scrubbed environments. The first scrub is in place: `tests/conftest.py` removes `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (any case) and sets `NO_PROXY` and `no_proxy` to `*` for every test and the subprocesses it starts. It also removes the app's own settings variables, so the shell does not leak into a test, and every `PG*` variable, which libpq would read and `app/db/connect.py` refuses. Since M1 PR 6 it removes every `ANTHROPIC_*` variable in any case, the key included, and `PYDANTIC_SETTINGS_DEBUG`.
