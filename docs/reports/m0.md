## What is shaky

- **The advisor boundary has never served a real document.** Row-level security, the pool guard and the registry are tested on planted rows and a test-local handler; the loader, retrieval and the real handlers are M1.
- **The residual risk of a forged `set_config`** through SQL injection as the app role is narrowed, not closed: the hygiene scan, `VerifiedAdvisor` and the pool guard. The SQL-hygiene and identity scans read names in the syntax tree; `getattr()`, `globals()` or strings defeat them. A signed advisor context is a later ADR.
- **The registry checks names and schemas, not meaning.** A field named `note` that a handler treats as an advisor id passes; frozen models are shallow (a `list` field can still change); a model can show another schema than it validates (PR 6 sec-2).
- **`Untrusted` prevents accidents, not intent.** `_value` and `__getstate__()` still reach the text (M2).
- **Trust auth on the local database:** any local process can connect as any role, the superuser included. Accepted for synthetic data; Azure is Entra-only from M3.
- **Offline enforcement** covers in-process Python sockets only. libpq, subprocesses and Chromium rely on loopback-only URLs, the import allowlist and scrubbed environments.
- **The dev login's peer check** rests on uvicorn's h11 protocol taking `scope["client"]` from the socket while `proxy_headers` is off; the browser's `Origin: null` under `no-referrer` was measured in Chromium only.
- **The gates score nothing.** Evals and red team have no cases, so "eval gate green" means "the corpus is well-formed". The first numbers come in M1.
- **The embedding model is not run yet.** CPU speed is unmeasured, the German evidence is public MTEB, and the licence sits in card metadata only (ADR 0005). The fake embedder carries no meaning.
- **One supply-chain fetch is not hash-pinned:** Chromium from Playwright's CDN, in `make web-deps`. The ubuntu-24.04 runner carrying Chromium's libraries is no longer a guess: `web-test` has run without `--with-deps` since PR 4, and the fallback container was never needed (`tests/ci/test_workflow.py` still forbids it).
- **One local database per machine.** `compose.yaml` names the project `sitrep`, so every checkout shares one container; the fresh-clone path reuses its data unless `make down` runs first (runbook, "From a fresh clone").
- **Time:** M0 took 12 calendar days against a plan of 3 to 4 days.
- **The ruleset is not verified here.** Required checks and SHA pinning are Timur's settings, applied after PR 4; the agent did not read them in PR 9 (its `gh api` call needs a yes).
